# Photoshop 上传插件验收标准

版本：验收标准 1.0。适用于 GameUI 蓝湖上传插件的隔离试用交付。本文定义验收要求，不代表候选已通过。现有线上格式以[冻结契约](CONTRACT.md)为准；本文的 `extensions` 是本期新增的兼容性验收项，不是当前已发布字段，也不要求本期实现所有语义标注 UI。

## 一、职责分工

PS 插件负责保存只有设计端才能准确提供的信息：原始素材、画板与图层事实、设计师明确标注的意图。蓝湖负责上传、存储和回读；Unity 负责把这些信息转成项目里的资源、组件和 Prefab。**有歧义就留给人确认，不由上传插件猜。**

| 事项 | PS 上传侧要做 | 不交给 PS 插件决定 |
| --- | --- | --- |
| 九宫格 | **本期必验。**记录真实 1× RGBA 小原图、源宽高、源像素 L/T/R/B、采样、资源版本；实例引用该版本并保留完整目标框，含透明留白。 | Unity Sprite 导入、Sliced 展示、图集及压缩。不能把目标大图当源图，也不能用设计倍数换算源边距。 |
| 通用图片 | **本期必验：**同一九宫格资源跨稿可显式选同一 `assetRef`，不靠名字或像素猜；普通切图走原流程。**后续：**普通公共图可标显式资源引用/候选键。 | Unity 决定公共库归属、复用、复制或归档；PS 不填 Unity GUID，不承担跨蓝湖画板搜索。 |
| 通用 Unity 预设 | **后续扩展。**可选标注设计角色、内容槽位和设计参数，例如主按钮、标题槽。 | 从角色和槽位映射具体 Prefab、组件、脚本、动画和字段；缺映射就由 Unity 侧处理或停下来确认。 |
| 字体 | **本期护栏：**不得破坏原生蓝湖已能读出的文本与样式；**后续：**补原生数据没有的设计样式键、效果参数，不重复上传整套样式。 | TMP 字体、材质、语言回退与运行时文本适配；不上传字体文件或材质 GUID。 |
| 滚动列表重复项 | **后续扩展。**设计师可标动态容器、代表样例、同 Item 的状态样例及固定节点，引用明确图层。 | 重复项判断、抽 Item、混排/嵌套支持、数据绑定与复用池。未标注不等于动态项。 |
| 节点层级 | **本期护栏：**保持原生父子关系、同层绘制顺序、位置、可见性等原有数据；**后续：**允许显式语义分组、固定装饰和跨组关系提示。 | 不自动重组 PSD 或根据矩形包含重排 Unity 树；锚点、遮挡修复和资源节点剔除由消费侧处理。 |
| 命名 | **本期必验：**原名照传，ID 不从名字或位置生成；**后续：**可另传语义别名，不覆盖原名。 | Unity 节点/文件命名规范、重名处理、业务引用路径。 |
| 滚动列表挂载位置 | **后续扩展。**可分别标记滚动容器、可见裁切框、动态内容区域、固定标题或装饰；有明确方向/布局意图再标。 | 确定 `ScrollRect`、`Viewport`、`Content`、Item 和业务组件；不把整张底图或卡片并集默认当裁切框。 |

多分辨率、安全区、点击热区、运行时状态和生成后手改保护属于 Unity/联调验收。以后确有设计信息只能由 PS 提供时，可加扩展项，不为这些场景提前造必填字段。

## 二、本期必须传对的数据

- **画板与图层基线**：保留官方蓝湖已有的画板尺寸、图层树与顺序、坐标、文本/切图引用等。指定画板或全量画板按用户选择上传，画板作用域不可串稿；原生未标记旧稿结果与原流程等价。仅对明确标注九宫格实例的画布位置/大小做冻结契约允许的透明留白校正，不顺手改其他图层。
- **身份与作用域**：`documentId`、`artboardId`、已标记图层的 `nodeId` 独立于显示名称和位置。改名、移动、正常保存重开不换身份；同稿复制实例生成新 `nodeId`，确认后沿用原 `assetRef`。作为新稿复制或跨稿粘贴必须能区分新实体；来源不明时提示显式修复，不按近似名称或像素自动绑定。多画板逐画板隔离，不能把 A 的资源或图层关系错绑给 B。
- **资源与实例分开**：`gameUI.assets[assetRef]` 保存不可变资源版本；真实源上传后应有唯一 `sourceNodeId`，源节点 URL 实际可回读且 `exportScale=1`。源 `sourceSize`、`nineSlice`、`sampling` 属资源；实例只引用版本，传自己的目标位置和尺寸。相同版本的像素、尺寸、固定边或采样不能被覆盖；合法修改通过新版本。透明目标内容框与完整画布框分别核对。
- **本地与云端分开**：XMP 内的 PNG Base64、完整目标画布辅助记录、上传作用域等仅供本地与适配器使用，不把 `authoring` 或 `uploadScope` 原样上云。云上仅保留约定的元数据和蓝湖资源引用；登录凭据、机器路径、原始 PSD、调试输出和未经批准的本地数据不得进入新增 payload 或验收附件。

## 三、上传数据如何扩展

### 只加独立扩展，不改现有核心节点

- 保持 `gameUI.schemaVersion=1`、`assets`、既有图层 `gameUI.kind` 和 `requiredCapabilities` 语义不变。现有 C#/JS 只认可 `image` / `resourceSource` 核心标记；不要为文本、列表或普通容器随意写新的 `layer.gameUI.kind`。可选语义集中放在根 `gameUI.extensions`，以「发布方.能力」为键，每项形如 `{ "version": 1, "data": { ... } }`，独立演进，不挤进资源版本主键。
- **预留方向，不冻结业务字段**：`gameui.assetHints` 提供公共图片键；`gameui.componentHints` 提供预设角色和内容槽位；`gameui.textHints` 提供设计样式键或原生缺失的效果；`gameui.layoutHints` 提供语义分组、别名、列表样例和挂载锚点。本期验通用容器和透传，不要求做出这些标注界面或实现 Unity 消费逻辑。
- 下例仅用于证明扩展位置与图层锚定方式，并非已上线能力或完整上传 JSON。压测/兼容夹具应采用合成数据；实际业务扩展需先约定字段与支持版本，再启用。

```json
{
  "gameUI": {
    "schemaVersion": 1,
    "extensions": {
      "gameui.layoutHints": {
        "version": 1,
        "data": {
          "anchors": {
            "hint-scroll": { "lanhuLayerId": "layer-10" },
            "hint-clip": { "lanhuLayerId": "layer-11" },
            "hint-content": { "lanhuLayerId": "layer-12" },
            "hint-item": { "lanhuLayerId": "layer-13" },
            "hint-header": { "lanhuLayerId": "layer-14" }
          },
          "lists": [
            {
              "container": "hint-scroll",
              "viewport": "hint-clip",
              "content": "hint-content",
              "itemSamples": ["hint-item"],
              "fixedNodes": ["hint-header"]
            }
          ]
        }
      }
    }
  }
}
```

- **锚点是引用，不是路径**：示例中的 `hint-*` 代表未来语义能力启用后生成并持久化的独立 ID，不是图层名；已标记图层也可通过其持久 `nodeId` 锚定（具体扩展定义唯一的定位规则）。原生图层 ID 只绑定当前画板、本次云端快照，必须验证能回读且唯一。标注关系不许跨画板串用；孤儿、重复或自指锚点不得制造有效关系。未启用该扩展前，不要求给所有原生图层发持久 ID。
- **兼容和失败规则**：缺少扩展等价于旧稿。未知可选能力或未知扩展版本不应改变九宫格、普通切图与 Unity 现有生成行为；支持的已登记可选扩展在 `PS/XMP → export → 蓝湖 → 读取` 中要语义无损（不要求 JSON 键序一致），能编辑后重存的环节不得擦掉其不认识但允许携带的字段。未知核心 schema 或未知**必需** capability 要明确拒绝，不能假装完成或降级成错误 Prefab。新增必需能力只能在 PS、蓝湖回读和 Unity 都有明确支持后启用；核心破坏性变化走新 schema 与迁移计划。
- **对外上传边界**：上线前为扩展的键名、类型、必选项、作用域、单项和总体字节/条数上限写明规则，并验证错误版本、超限和非法引用。只把登记允许的扩展发到蓝湖；不认识的本地私有数据原样留本地，不走透传出口。允许上云但尚无消费者的测试扩展用于验证通道。可选标注不合法时显式提示并由用户修复或明确移除标注后再传，不得静默替换。若蓝湖实测剥掉扩展，记录失败并另行评审承载方式，不得宣称已预留好云端扩展。

## 四、可打勾的验收门槛

所有项目初始为「未验收」，按**同一候选包**分别记录「通过 / 失败 / 阻塞」。不将历史旧包或不同候选的测试拼成一次通过。

| 编号 / 环节 | 必须执行的动作 | 通过标准与证据 |
| --- | --- | --- |
| PS-01 真实宿主操作 | 用待验安装包在目标 Photoshop 实际打开面板，选择测试项目、平台、设计倍数、指定画板；操作定义/引用并应用、保存重开、实际点击上传。覆盖小面板列表/滚动。 | 记录版本、包 SHA-256、宿主版本、真实操作录屏或可核对截图。入口可用、选择不串、面板报告上传阶段；「已交给蓝湖」不是「上传成功」。 |
| PS-02 普通稿回归 | 用同一未标记样例、画板、平台及倍数对比原流程；包含组嵌套、普通切图与文本。另试多画板选传。 | 除请求时间等非语义差异，层级、顺序、可用文本样式、资源及框与基线等价；没有被选外的画板或污染原生数据。保留对比结果。 |
| PS-03 身份与跨稿引用 | A 定义版本，B 通过目录显式引用同版本；改名、移动、保存重开、复制实例；再用同名不同源、修改像素/边距/采样与来源不明的复制作为反例。 | A/B 实例共享同一个版本，复制后的实例 ID 独立；同名不会误绑，禁止用旧版本覆盖不同内容。提交本地和云端脱敏身份映射及失败提示。 |
| PS-04 真实素材与透明目标 | 用非对称边距的 Point 源、带透明边的源、Bilinear 软边样例；至少两个设计倍数；包含恰好能容纳固定边及小一像素的目标。 | 取回蓝湖实际原图并独立解码，按 PNG 尺寸和解码 RGBA 核对 1×（不以 PNG 文件字节等同取代像素核对）；核对各实例完整目标框、留白、border、sampling。非法尺寸被拦，不产生声明成功的画板修订。 |
| PS-05 扩展往返与向后兼容 | 用一个已准入但 Unity 不消费的测试扩展，含嵌套对象、新增可选字段和图层引用；保存重开、编辑一个既有字段、真实上传并回读。另测不带扩展、旧消费端不认识但已准入的可选版本、未知核心 schema、未知必需能力及非法/超限数据。 | 官方云端读回实际保留允许字段，旧 Unity 导入未受影响；未知核心 schema、未知必需能力或非法数据明确报错，私有字段不上传。提交各环节 JSON 差异与拒绝用例记录。仅本地 mock 成功不算云端通过。 |
| PS-06 上传护栏和失败恢复 | 测未登录/取消授权、选错项目、缺画板、重复点击、断网或超时，以及恢复后重试。保证生产侧只做隔离门禁反例，不发真实生产上传。 | 不允许提交时不启动上传；面板区分未开始、处理中、失败、结果未知与已确认成功。结果未知先查云端再重试，不能静默产生重复修订或报成功；失败后原 PSD 不被插件意外改动。 |
| INT-01 Unity 真实闭环 | 从 PS-03/04 同轮上传的两份实际云端修订导入两个隔离模块；保存重开、重跑、对比渲染。另验证未注册能力不受影响。 | Unity 能按同一个已登记 `assetRef` 复用同一 Sprite GUID，边距/采样/画布框正确；无变化重跑不新增资产。Point 按整数像素对照；Bilinear 按匹配的背景、颜色空间和采样条件对照。保留云端修订、Unity 日志、Prefab/Sprite 引用和截图。 |
| REL-01 安装与正式推广 | 用拟发布形态验安装、升级、卸载/回滚，覆盖实际重启及恢复，不替换未知/外部改动的官方包。 | 按[交付流程](../DELIVERY.md)留痕；开发工具加载不等于正式分发通过。正式包、支持范围和美术试用未过，不开放生产范围。 |

### 回交材料与放行规则

- 一条可复跑链路：源码 commit、包版本与 SHA-256、PS/UXP 环境、两份合成测试稿、输入画板与倍数、实际云端修订、脱敏云端 JSON/资源核对、测试日志，以及每个失败项的复现步骤。只读回核对，别为了让测试通过去补写结果。
- **PS 插件交付通过**：PS-01 ～ PS-06 同包全部通过；未测或无法回读记为阻塞，不记通过。此时可签插件交付，不等于可正式推广。
- **端到端/推广通过**：同一候选的 INT-01 由 Unity 集成负责人确认；正式推广额外要求 REL-01 通过。角色、字体、分组、滚动等未来扩展只有在本期明确纳入实现时才新增专项，不把「留好通道」写成「功能已上线」。
