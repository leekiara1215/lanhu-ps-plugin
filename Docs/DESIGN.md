# GameUI Photoshop 插件设计

本文是插件行为、模块边界和后续设计变更的主文档。初始设计基线为 2026-11-19 工作区中的面板候选 `0.6.20`。检出其他提交时，可用对应的 manifest 确认代码版本。实机通过情况按候选版本查阅。[面板 manifest](../Panel/manifest.json) · [验收快照](ACCEPTANCE.md)

## 目标与边界

- 美术在 Photoshop 内完成三类工作：上传设计稿、标记普通切图，以及收录原始源图并制作可跨稿复用的九宫格。插件保存 PSD 中的设计事实、用户明确标注的资源版本和几何信息。
- 蓝湖负责原生画板与切图的导出、上传和云端提交。GameUI 适配器在固定的原生流程中补充九宫格数据。集成面板的上传范围限隔离测试项目 `cfea1199-7c07-48d9-86ef-cdbd3385c237`，界面与上传出口均校验该范围。[兼容清单](../compatibility.json) · [蓝湖宿主桥接](../Panel/lanhu-host.js)
- PSD、素材像素与图层标注由本插件维护。Unity 的资源登记、复用和 Prefab 生成由 Framework 实现。本仓是插件开发源，Framework 通过审查后的指定提交同步插件快照。[冻结契约](CONTRACT.md) · [开发与集成同步](MAINTENANCE.md)

## 面板与操作流程

面板默认打开「上传」，顶层有「上传」「切图」「资源」。「资源」包含「公共资源」和「九宫格资源」，返回时恢复上次打开的资源子页。各页恢复会话中的滚动位置。下拉菜单统一使用滚动区外的浮层，根据可用空间向上或向下展开，字段离开可定位范围时关闭。原生输入框在被浮层遮挡或超出视口时暂时隐藏编辑层，保留输入值。[面板结构](../Panel/index.html)

### 上传

1. 通过浏览器授权或账号密码登录。浏览器授权支持等待、取消与超时。登录后的团队位于顶部，依次确认平台与设计倍数、全部或选中画板、项目和分组。留空分组表示项目根目录。账号设置、上传主操作及结果操作位于底部。
2. 面板显示实际待上传画板与数量。显式选择「选中画板」时，空范围会禁用上传。无原生画板的 PSD 使用蓝湖原生整稿入口。点击上传时冻结文档 ID 和画板 ID 列表，刷新后复核，再由原生预检、队列及导出入口继续验证范围。
3. 上传结果按画板显示进度和失败原因。文件传输完成后，项目提交以及所选分组须获得确认才显示成功。回执不完整、提交超时或分组确认缺失时显示待确认，并提供网页核对入口。可重试的失败项按原批次 ID 重试，先复核同一 PSD、原去向和设置。「仍然上传」只在原生流程返回可直接提交的无变化数据时出现。已确认成功时可打开设计页或通知项目成员。

[蓝湖宿主桥接](../Panel/lanhu-host.js)

### 切图

切图与上传共享同一蓝湖运行时。选层可做紧贴元素切图（`-h-`），也可创建框选组（`-s-`）及 `-slice-` 辅助层。固定宽高各自可选，留空的轴由原生流程采用图层尺寸。紧贴标记可直接改成框选，已有框选须先取消再改尺寸。区域显隐控制辅助层可见性，切图文件随设计稿上传。取消标准框选时，删除辅助层，再用 Photoshop 原生解除分组并核对原图层 ID 与顺序。无法确认是标准切图组时保留组结构并清除标记，遇到异常辅助层或操作失败则请求回滚本次历史记录。[蓝湖宿主桥接](../Panel/lanhu-host.js)

### 公共资源与九宫格

- 「公共资源」从未绑定九宫格的选层收录全分辨率原始 PNG，写入插件私有目录。可按版本选择并导出原始 PNG，也可显式导入或导出目录 JSON。新建时拒绝与目录中已有资源同名，提示改用现有资源。
- 「九宫格资源」可从当前选层新建九宫格源图，也可为已有公共源图登记九宫格参数，沿用该源图的 `assetRef`。选用已配置版本时继承固定边和采样。选择资源只改变面板状态，主按钮才执行创建或引用、目标像素应用与 XMP 更新。未初始化的 PSD 可在主操作中自动初始化。
- 选中已绑定图层时恢复它自己的 `assetRef`，默认收起列表并提供「应用尺寸」。切到未绑定的图层时从空引用开始，复用需显式选择。已配置的版本可按目标尺寸预览。高级操作提供初始化、新建、改名、发布新版本、仅引用、复制实例、分配独立文档身份、检查定位和修复。PSD 由美术通过 Photoshop 正常保存。
- PSD 选层、打开和关闭通知驱动刷新。忽略过期的异步读取结果，并保留读取期间对当前选层新编辑的字段。上传与资源修改互斥，退出插件时清理通知监听及蓝湖运行时资源。

## 像素、身份与持久化

### 源像素和目标画布

- 源采集与九宫格应用要求 sRGB IEC61966-2.1、8-bit RGB PSD，且选中单个普通非背景像素层。层和父组须可见、满不透明度及填充，使用 Normal 或父组的 Pass Through。蒙版、图层样式、剪贴、画板等会触发拒绝。当前面板的九宫格编辑不支持原生画板内部，上传适配器可读取画板内已有的有效标记。
- 源快照使用整数 `boundsNoEffects` 加用户在新建九宫格源图时显式填写的透明留白，按 1× 采集并生成确定性的 8-bit RGBA PNG。公共资源直接按选层边界收录。宿主裁去的留白仅在已声明画布范围内补透明。源及预览各限 4,194,304 像素。
- 固定边使用源像素整数 L/T/R/B，中心拉伸。源图须留有可拉伸的中心，目标宽高至少容纳对应的固定边总和。采样为 Point 或 Bilinear，缺省 Bilinear。预览及应用从同一份源快照渲染，应用后用 Photoshop 实际内容边界核对透明目标画布。纯透明结果无法建立有效内容框，会拒绝。

### PSD XMP、目录与云端

- **PSD XMP** 使用 GameUI `schemaVersion: 1`。`nodes[Photoshop layer ID]` 记录持久 `nodeId` 与 `assetRef`，`assets[assetRef]` 记录资源契约。`authoring.version: 1` 下的 `sources[assetRef]` 保存尺寸与 PNG Base64，`targets[nodeId]` 保存完整目标宽高、左上留白和实际内容宽高。`uploadScope` 记录隔离上传范围。XMP 写入后立即回读，损坏的 JSON 会报错并要求修复。
- **资源目录** 新写入 `gameui-resource-catalog-v2.json`，缺少该文件时读取旧 `gameui-resource-catalog.json`。可携带目录 v2 按 `assetRef` 分开保存 `assets` 与 `nineSlices`，`authoring.sources` 保存快照。普通源图可以只有 `assets` 和源快照。目录读取兼容 v1，无图层绑定或实例 `targets`。同一资源版本的合并会校验源像素和契约，读取失败时阻止常规覆盖，可显式导入备份恢复。
- **蓝湖 payload** 仍为 GameUI `schemaVersion: 1`。`authoring` 与 `uploadScope` 仅供本地和适配器使用。云端资源引用 `sourceNodeId` 与蓝湖 PNG URL，并带 `exportScale: 1`。`nineSlice.v1`、`sampling.v1` 是当前已知必需能力，显式采样声明 `sampling.v1`。未知 schema 或未知必需能力须拒绝。扩展字段的作用域和往返验证遵循上传验收标准。

### 资源版本与文档事务

`assetRef` 使用 `assetKey@version`。显示名可以调整，身份保持稳定。已登记版本的源像素、源尺寸、固定边、采样及其他资源契约字段保持不变，改变这些值须发布新版本。公共源图首次登记九宫格参数可保留原版本。实例继承资源契约，复制实例生成新 `nodeId`，以新 ID 保存一份目标记录并沿用资源引用。明确为副本分配新身份时重建文档和实例身份。遇到来源不明的图层，要求显式选择资源或修复身份。[创作逻辑](../gameui-authoring.js)

涉及 PSD 的创作操作通过 Photoshop `executeAsModal` 与历史事务完成，进入时复核文档和选层。写入按先存目录、后写 XMP 的顺序进行。若 XMP 写入失败，面板请求回滚 PSD 的像素与元数据，已写入目录的合法源快照可供显式引用恢复。目录写后回读校验，宿主文件接口未提供断电原子性保证。

## 蓝湖导出适配

1. **确认选传范围。** `prepareAnalysis` 在原生分析前对照实际 PSD 图层树和选传清单。原生画板上的 `artboardId` 由持久 `documentId` 与 PSD 原生画板图层 ID 共同确定。无原生画板的稿件沿用 XMP 中的 `artboardId`。既有原生画板修订若依赖旧的单一文档级 `artboardId`，迁移时须独立核对绑定关系。
2. **按画板提取。** 原生格式化后，`capture` 复核画板与图层来源。普通画板沿用原生数据。标记画板仅携带本画板的标记及引用资源，同一 `assetRef` 跨画板复用时，每张涉及的画板各自携带一份来自同一快照的源节点。归属不明、选传范围不一致、源缺失或多画板根字段无法安全分配时拒绝导出。
3. **准备源 PNG 和实例几何。** 既有原生源节点可沿用，需注入的 1× 源节点只存在于导出数据。集成版对本批已核实的九宫格实例使用原生裁剪流程生成校验图。普通命名的实例保留原图层名称，无需添加蓝湖切图前缀。带 `targets` 的实例先核对原生内容框，再用当前内容位置减左上留白恢复完整画布，并在 `gameUI.nativeReferenceFrame` 保留原生裁剪参考。旧稿缺目标记录时保留原生框。原生缩放等操作导致内容尺寸与记录冲突时，提示回面板重新应用。
4. **交回原生提交。** 由原生上传链路传输资源。`finalize` 验证源和实例上传状态，写入云端源节点引用、URL 和 1× 尺寸，再交由蓝湖提交。旧审计稿兼容路径及官方插件目录的适配器按固定契约处理，未标记稿沿原生导出。

## 模块和交付形态

- `Panel/manifest.json` 和 `Panel/index.html` 是 UXP 入口。面板使用独立 ID `com.bettagames.gameui.authoring.test`，要求 Photoshop 25.0 以上和 API 2。`panel.js` 装配工作区与生命周期，`ui/` 负责导航、控件与提示，`workspaces/` 负责页面状态，`domain/parameters.js` 解析输入和上传范围。
- `Panel/application/` 负责目录、创作与 PSD 事务，`Panel/adapters/catalog-storage.js` 适配 UXP 文件读写。根目录的 `gameui-authoring.js` 和 `gameui-core.js` 保存可离线测试的资源与像素逻辑，`gameui-ps.js` 连接 Photoshop XMP、图层及像素接口，`gameui-export.js` 负责上传契约。
- **独立面板**由 `Panel/build-panel.cjs` 在源码树外的新目录或空目录生成。基础构建提供本地资源工作区，使用 Adobe UXP Developer Tool 加载。集成构建显式提供蓝湖 UXP `1.0.32（303）` 原包，校验 manifest 和入口文件 SHA-256 及注入位置，再生成 `lanhu-runtime.js` 和来源清单。`lanhu-host.js` 用插件独立会话和宿主桥接驱动原版业务模块。集成 staging 增加网络及外部 HTTP(S) 打开权限。
- **隔离试用安装包**由 Adobe UXP Developer Tool 将验收过的集成 staging 打包为 CCX，沿用隔离试用插件 ID。收件人通过 Creative Cloud 安装，并使用自己的蓝湖账号登录测试项目。CCX 只包含运行所需的插件文件、图标和说明，安装记录与包 SHA-256 单独核对。
- **官方插件目录适配器**由 `build-audit-patch.py` 根据同一固定构建生成。`gameui-delivery.py` 提供确定性 ZIP 和独立的安装、升级、诊断、卸载、恢复及回滚入口。磁盘变更须显式指定官方插件路径与外置持久状态目录，使用哈希、快照和事务日志，遇到未知版本或外部改动须停止。面板 UDT 加载与官方插件目录适配器是独立入口，需分别验收。

## 验证与变更规则

- 用与改动对应的测试验证。创作、XMP、身份和像素检查见 `test-authoring.cjs`、`test-gameui.cjs` 及 `test-production-fixtures.cjs`。面板交互见 `test-panel-layout.cjs`，蓝湖宿主及导出见 `test-lanhu-host.cjs` 和 `test-export.cjs`。固定官方模块 harness 和安装生命周期测试使用经校验的原版副本。步骤与输入见 [离线测试](../README.md#离线测试)及[交付手册](../DELIVERY.md)。
- 0.6.21 在 Photoshop 28 实传两份复用旧目录资源的稿件并回读云端 GameUI v1 和 1× 源图。完整混合多画板、Unity Prefab 生成和生产推广仍分别验收。官方功能对照和上传验收门槛见下列文档。[验收快照](ACCEPTANCE.md) · [蓝湖功能对照](LANHU-PARITY.md) · [上传验收标准](PS-UPLOAD-ACCEPTANCE-STANDARD.md)
- 更新设计先修订本文，再按修订后的设计实现。更新插件代码时，在同一次变更中同步本文中的受影响章节，核对用户流程、模块责任、数据与兼容契约、失败处理和验证范围。仅有实现调整时，在相关章节简记调整内容和行为核对结论。
- 冻结的跨端接口由 [CONTRACT.md](CONTRACT.md) 定义。涉及冻结接口的设计变更先与集成负责人确认，再同步契约、本文、实现和对应验收。使用步骤、发布证据和回交记录各自在原有文档维护，本文引用具体出处。仓库级规则见 [AGENTS.md](../AGENTS.md)，日常流程见 [维护与同步](MAINTENANCE.md)。
