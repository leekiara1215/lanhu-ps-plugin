# GameUI 独立 UXP 美术面板（隔离试用）

入口：`Panel/build-panel.cjs`。从 Photoshop 工具目录执行：

```sh
node Panel/build-panel.cjs /absolute/new-or-empty/staging/GameUIAuthoring
```

输出为自包含插件目录，包含面板运行文件、说明和 CCX 所需图标。构建器拒绝覆盖非空目录。开发加载入口为输出目录的 `manifest.json`，支持 Photoshop 25.0 或更新版本，使用 UXP API 2。可通过 Adobe UXP Developer Tool 的 Package 生成 CCX。Node 构建和测试不启动 PS/Unity。

## 上传、切图与九宫格

0.6.14 默认打开「上传」。登录后确认去向、设计倍数、画板范围，点击固定在底部的「上传 N 个画板」；首次未选好测试项目时展开去向，之后按需展开。显式选「选中的画板」但没有可上传画板时不会回退成全传。上传交给内置蓝湖流程前重新读取原版画板范围，文档或范围与刚才显示的不一致时取消本次操作。部分成功和结果不明只提示先核对结果，不自动重传。

0.6.15 的多画板九宫格导出会在原版队列和解析入口复核选传范围，再沿 PSD 图层树验证标记归属。普通画板按原版导出，有标记的画板仅携带本画板的标记和资源。多个画板共用同一资源版本时，每张标记画板各自包含 1× 源节点。缺少可验证归属或可用源时停止本批导出。当前面板支持导出已有标记，原生画板内的九宫格编辑仍受限制。真实 Photoshop 上传和云端回读待验收。

0.6.16 等待蓝湖进入上传页后再判断是否启动。预检通过后，已确认的画板范围保留到原版队列及导出入口复核。普通切图按 Photoshop Rectangle 的坐标字段裁剪。

0.6.17 将「公共资源」和「九宫格资源」分为两个入口。「公共资源」收录选层的原始像素，可导出源 PNG 或导入、导出资源目录。「九宫格资源」可以选同一个源图版本，另填固定边和采样，再应用目标尺寸。目录 v2 的 `assets` 和 `nineSlices` 按 `assetRef` 关联，普通源图可单独存在。新目录文件与旧文件并存，旧目录可直接读取；PSD 和蓝湖仍使用 GameUI v1 上传契约。普通源图的目录记录保存在本地。

「切图」直接标记 Photoshop 的选中图层或组，切图跟随设计图上传。显示/隐藏只控制画布上的区域。三页保留各自滚动和本次会话的上传设置，不自动上传。「九宫格资源」是可选入口，仅首次打开才读取本地资源目录；目录不可用也不影响普通上传。已绑定时收起资源列表，默认只改宽高；切到未绑定的新图层时不沿用上一个图层的资源。已有资源可选预览，高级操作仍可用。

详见 [蓝湖官方功能对照](../Docs/LANHU-PARITY.md)。不包含固定蓝湖运行时的独立构建仍可创作九宫格，但不能登录、切图或上传；在此构建中请直接进入「九宫格资源」。

## 界面历史

0.6.13 停用隐藏蓝湖界面中 Popper 的滚动与缩放监听，避免它在脱离页面的 DOM 上反复查找滚动父节点。可见菜单的浮层本身覆盖选项区域，并在关闭后隐藏；按下选项时保留字段焦点，点击后提交选值。

0.6.12统一菜单与滚动边界：六个下拉菜单挂在滚动视口之外的 `panelOverlays`，以绝对定位贴合字段，不参与卡片排版，也不计入内容滚动高度。默认向下，空间不足时向上，列表高度受内容视口限制；滚动、缩放和布局更新后重新定位，字段部分滚出视口时关闭。菜单内滚轮在边界也不传给外层，点击浮层内部不会误关。保留精确值、禁用项、键盘选择和单菜单约束。

三个顶层页签共用切换入口：关闭菜单、结束拖动，保存和恢复各页滚动，再更新滑块和输入层裁剪。浮层覆盖原生 input 时暂时隐藏该编辑层，菜单关闭或移开后恢复，输入值不变。这遵循 [Adobe UXP 已知限制](https://developer.adobe.com/photoshop/uxp/2022/uxp-api/known-issues) 中的原生编辑层遮挡说明。Chrome 排版回归不等同于 Photoshop 宿主实机验收。

浏览器回归使用当前HTML/CSS/JS与隔离的业务桩，不访问蓝湖、PSD或私有目录：

```sh
node --test --test-timeout=10000 test-authoring.cjs
GAMEUI_PLAYWRIGHT_MODULE=/absolute/path/to/playwright-core node --test test-panel-layout.cjs
```

浏览器须已安装Chrome及Playwright/Playwright Core；不提供模块路径时该可选回归会明确跳过。实际检查320×480、360×600、400×640、800×600下的六个菜单，展开前后字段/下方元素/内容高度/主滚动范围不变、命中浮层、输入遮挡、打开时缩放、向上展开、外层滚动跟随/越界关闭、菜单滚动边界和页签/键盘焦点切换。

0.6.10修复真实PS中蓝湖初始化报错、浏览器授权按钮停留在“连接失败”的问题。UXP的`window._`是带自有`bind`工具的函数，桥接不再把它当作普通宿主方法绑定，并改用`Function.prototype.bind.call`转发方法。真实PS28中已通过调试入口验证初始化、打开浏览器授权、自动取得登录及读取2个团队/5个项目；未通过自动化直接点击浮动面板按钮，未执行上传或PSD写入。

0.6.9在插件名称和“资源创作”页签上标明版本。整个插件采用原版蓝湖浅色样式的白底、蓝色头栏、#2878FF主按钮、蓝色下划线页签、细边框表单和分区卡片；资源设置、目标尺寸与高级操作使用同一视觉规则。蓝湖页直接呈现当前插件自绘的组件，按蓝湖的团队 → 项目 → 设计倍数 → 画板 → 上传顺序组织，不再显示“加载蓝湖工具”的说明落地页。提示使用中文，原始诊断保留在高级操作底部。

0.6.4用户实机截图显示，CSS外框已变化，但原生button仍绘制灰色胶囊、input保留深色边框，不能把上一轮CSS/DOM回归称为实际控件样式通过。0.6.5将全部静态/动态按钮、页签改为普通div自绘控件，保留原ID与完整assetRef；集中维护disabled属性、aria-disabled、tabindex及点击/Enter/空格门禁。输入与下拉继续使用可编辑原生元素，增加appearance重置、显式不透明白底、高优先级前景/边框和固定高度。此调整不改XMP、资源和上传协议；仍须在当前PS宿主实际确认控件颜色、尺寸与可操作性。

0.6.6按后续实机截图修正仍为深灰色的原生下拉框及滚动时输入框覆盖固定顶部栏的问题。六个选择器（团队、项目、分组、平台、倍数、采样）改为自绘combobox/listbox；禁用态保持浅底，不能越过登录、上传忙碌与测试项目门禁。当时选项列表在内容区内展开并可滚动（0.6.12已改为浮层），支持上下/Home/End、Enter/空格、Escape/Tab和点击外部关闭，同一时刻只展开一个；相同状态刷新不重建菜单。选项使用完整值，不按显示名称选择或自动猜第一项。采样仍为Point/Bilinear，分组空值仍为项目根目录。原生input仍负责编辑，滚动/布局变化时将越过内容视口边界的编辑层暂时隐藏，返回完整可见区后恢复；不清空值、不改PSD。实际宿主滚动与键盘表现以验收记录为准。

蓝湖页包含账号密码登录/退出、实际团队/项目/分组列表、平台与设计倍数、全部/选中画板、上传入口和实际流程进度，以及选层切图、切图分组、取消/显示/隐藏切图。项目列表对非测试项目禁用，后端仍严格校验固定测试项目。列表来自真实业务读取，不填示例账号/项目/画板；失败保留控件并可通过“刷新账号与项目”重试。当前未接入自绘的验证码、新建云端项目、设置菜单全部功能；不再提供官方面板跳转入口；这些未实现功能仍不宣称已支持。

0.6.3新增“从浏览器获取授权”：使用原包UUID/域名助手生成连接，打开蓝湖 plug-bind-account 页面，按原接口查询该连接的授权结果，成功后更新同一会话并刷新团队/项目。等待可取消，五分钟超时；取消、超时或销毁后忽略迟到响应并清理计时器。浏览器端登录/SSO由蓝湖网页处理，真实授权闭环仍待验收。取消等待不等于撤销已在网页授予的权限。

0.6.8移除资源创作页“蓝湖协作”卡片、状态提示和所有内联展开/快捷上传入口。账号、团队、项目、上传与切图仅在独立“蓝湖工具”页签呈现，由本插件绘制并维护同一会话；切换不搬移组件、不重置创作输入，不写PSD或目录。首次进入蓝湖页连接内置业务模块，资源创作页不主动连接。密码仅用于请求并清空输入，不出现在状态快照。实际上传期间继续阻止资源创作和蓝湖设置/切图重入。

业务模块内置于本插件，不调用已安装的官方插件、不读取其私有登录存储、不申请IPC权限，也不提供官方插件跳转入口。当前业务适配仍复用固定原包的Vue/store/路由和上传链路，并非已经重写全部蓝湖API。运行节点和样式放在脱离页面的私有节点树中，不插入原版页面、不依赖Shadow DOM，不再触发隔离界面提示。750ms计时仅读取内存状态，不轮询网络；刷新读取列表，仅在明确点击浏览器授权后启动最多五分钟的有限会话查询。销毁时清理计时器、事件、Photoshop通知和Vue。节点作用域不是权限沙箱，不保证取消已发网络请求；真实宿主登录、切图和上传仍须验证。

右侧主滚动条使用浅灰轨道和圆角滑块，与卡片和分割线统一；主视口不使用宿主绘制的滚动条。滚轮优先交给有剩余空间的资源/画板列表，再滚动面板；下拉浮层独立消费滚轮。支持滑块拖动、轨道翻页、PageUp/PageDown/Home/End及轨道方向键，保留输入和选择器自身按键。布局变化同步滑块和输入层裁剪，销毁时移除监听。顶部页签分割线为显式1px浅灰节点。标签统一为“目标画布宽度 / 目标画布高度”、四方向“边框”和“留白”。

下拉列表也使用自绘浅色滚动条（10px轨道、6px圆角滑块），以同一偏移移动选项与滑块，不依赖宿主原生滚动条或隐藏视口的scrollTop。短列表按内容高度收起轨道；长列表支持滚轮、拖动、轨道翻页和键盘，选项高亮自动滚入可见区，0.6.12起到达边界也保留菜单内滚轮。关闭、禁用或销毁时释放拖动监听。两列字段显式顶部对齐，展开平台列表时设计倍数不再随较高的列居中下移。本次 `node --test test-authoring.cjs` 59项通过，Chrome的320/400px布局预览通过；0.6.11已通过UXP Developer Tools加载到Photoshop 28，状态为Loaded并提示Plugin Load Successful；主窗口截图未包含插件浮层，因此不将加载成功表述为实机布局与滚动已验收。

0.6.7曾用隐藏视口的scrollTop驱动主滚动条，用户实机反馈配色正常但内容没有联动；不将该版离线模拟通过当作宿主滚动通过。0.6.8改用同一内部偏移同时驱动内容节点的相对top和滑块位置，范围来自内容自身高度，不再依赖隐藏视口scrollTop。兼容wheel与mousewheel字段并抑制重复事件。回归模拟scrollTop始终为0的宿主，检查滚轮、拖动和翻页确实改变内容位置及滑块；实机交互仍以用户验收为准。

用户随后纠正：0.6.8右侧滑块拖动正常，缺少的是“按住左侧空白处上下拖动”。0.6.9仅新增内容区拖动手势，共用原有内容/滑块偏移，不改已确认的右侧拖动与配色。优先使用pointer capture，兼容无捕获能力的鼠标事件；移动4px后开始，范围限制在内容上下边界。输入、按钮、选择器、列表、标签和文字区域不接管拖动。松手、取消、失焦、切换页签及销毁时释放捕获和监听。58项面板离线回归通过；实机空白区拖动仍待用户确认。

只连接/登录/选项目/改上传设置不改变PSD；切图按钮会修改原生选层切图设置，上传和切图都只由明确点击触发。API2导出和切图保留modal及Promise所有权。冻结gameUI协议及私有目录位置不改，所有集成上传仅限测试项目 `cfea1199-7c07-48d9-86ef-cdbd3385c237`。

### 构建带蓝湖功能的候选

```sh
node Panel/build-panel.cjs /absolute/new/staging/GameUIIntegrated --official-plugin /absolute/pinned/original/lanhu
```

输入须是 `compatibility.json` 白名单的原版 manifest/index，构建前逐字节核对 SHA。构建在新输出中生成 `lanhu-runtime.js` 和带原包及生成文件哈希的 `lanhu-runtime.json`。基础包提供公共资源和九宫格编辑，蓝湖上传与切图需要集成构建。

完整集成候选在 staging manifest 增加 network.domains=`all`（原版服务动态返回OSS端点）及 http/https 外部打开权限，基础构建不增加网络权限。登录使用当前独立插件自己的存储，不读取或复制官方插件的私有登录数据。候选尚未证明实际PS中的自绘控件可操作性、私有业务模块初始化、登录回调、切图/上传和云端回取兼容；真实宿主、网络及Unity仍交总控验证，不将离线测试当作正式替代蓝湖插件通过。

## 日常操作

1. 打开 PSD 并选一个普通像素层。选择器空值明确表示“新建公共资源”，不会自动选择库中的第一条。首次新建只填名称、源像素 L/T/R/B、Point/Bilinear 和需要的源透明留白；内部ID与版本仍自动维护。同名新建会阻止并提示引用现有资源，独立资源需不同名称。
2. 填目标画布宽高，点击唯一主按钮。新建时先从当前原尺寸采源快照，再创建引用并应用目标像素；引用时明确选择已有资源，由资源继承九宫/采样，不从效果图推断源。未标记 PSD 在同一次操作中自动初始化，无需另点初始化。
3. 使用正常 Cmd+S 保存 PSD。面板不执行隐式磁盘保存。下一未绑定图层或 PSD 可继续使用刚明确选择 / 创建的资源，一次主操作完成引用与应用；绑定层切回来会显示自己的持久 assetRef。

目标尺寸默认取当前绑定实例已登记的完整画布，或当前选层整数非空边界；后者不代表原始透明画布，需保留外沿时填写完整尺寸。source透明留白仍须明确填写，默认0不会猜原图画布。创建后原始1×快照始终保留在`authoring.sources`，目标几何保存在`authoring.targets`，不需要另摆源样本层。

资源以面板内可滚动的按钮列表显示，无需展开原生下拉菜单。第一行“新建公共资源”明确表示空引用；已有版本显示名字与版本，同名同版本附当前列表内区分序号。当前行显示“已选”并高亮；下方显示资源版本数量。各行的 `data-resource-ref` 及内部选择值始终为完整 assetRef，序号不参与身份、不会合并用户资源。默认界面显示当前资源的继承契约；内部全引用在高级诊断中查看。点击资源行只更新面板选择，不写 PSD 或目录，主按钮才执行引用与应用。

## 高级与自动刷新

“显示高级操作”展开既有分步操作：单独初始化、仅创建、更新名字、发布新版本、仅引用、复制/fork/身份修复、仅应用、目录导入导出及检查定位。选中已有资源版本时，可在目标尺寸主按钮旁选择预览。发布新版本仍按私有目录同资源最高版本+1；名称更新不重采样源。引用只把所选版本加入PSD，导入目录只更新私有库。

使用Adobe Photoshop API2 `action.addNotificationListener(["select","open","close"], callback)`，只在文档/图层身份改变时刷新；忙碌或加载中跳过，同一选层内的输入不会被通知重置。销毁插件时移除同一监听；API注册失败会提示使用高级刷新，不轮询。实际宿主事件时序仍由负责人验收。[官方API](https://developer.adobe.com/photoshop/uxp/2022/ps-reference/media/photoshopaction)、[事件名](https://developer.adobe.com/photoshop/uxp/2022/ps-reference/media/eventcodes)。

异步读取 XMP / 检查文档身份期间若继续切层、切文档或关闭文档，刷新会丢弃旧选层的结果并读取最新选择，再更新界面。读取期间在当前选层编辑的目标宽高及资源设置会保留；未编辑的字段仍接收该实例默认值。资源行与其它按钮在忙碌期间禁用，完成后恢复，避免操作中途切换资源。列表内容未变化时复用现有行，避免刷新重建列表而丢失滚动位置。插件销毁后不呈现未完成的读取结果。这些行为已有离线回归，真实 PS 中的可见、可选、滚动及通知时序仍需验收；旧原生菜单的宿主根因未确定。

主按钮将自动初始化、创建/引用、像素应用及XMP写入置于一次modal history；失败请求回滚PSD像素与XMP。未知schema/必需能力、损坏XMP或身份冲突仍严格阻止，不覆盖已有标记。目录沿用先存源后写XMP：后续XMP失败最多留下合法未使用条目，面板保留原错误并提示可显式引用恢复，不回写或删除可能被外部更新的目录。

## 支持边界

- 仅已使用 sRGB IEC61966-2.1 配置的 8-bit RGB 文档普通非背景像素层，拒绝隐式色彩转换。层及父层必须可见、100% opacity/fill、Normal（父组允许 Pass Through）。拒绝样式、蒙版、剪贴、调整层、智能对象、形状、文字、画板或无法读取描述符的层。请由美术明确在单独副本栅格化/合并，不自动破坏原层。
- 按整数 boundsNoEffects 加用户显式透明留白获取源像素，不猜测原始画布、不缩放，要求 imaging 返回 level=0、8-bit RGB(A)。请求 sRGB IEC61966-2.1、applyAlpha=false；RGB 返回补 alpha=255，RGBA 保留透明 RGB。宿主若裁剪无像素区，仅在声明的整数源画布边界内补透明 0。已有target时，“应用”按当前非空图层左上角减记录inset还原画布原点，普通移动后可继续保持同一画布；无target旧稿首次应用以当前非空左上角为画布原点。应用会刷新target并核对实际内容bbox；纯透明目标明确拒绝。最多 4,194,304 源/预览像素。
- PNG 为纯 JS 编码，RGBA8、filter 0、zlib stored blocks、CRC32/Adler32，确定性无损，不调用只输出 JPEG 的 imaging.encodeImageData。目录读取器只支持本面板生成的确定性 PNG 编码；任意外部 PNG 请从 PS 普通像素层重新定义。
- assetRef 版本的像素、源尺寸、border、sampling 以及未知资源契约字段不可改变；显示名字可更改。未知可选字段经复制/目录导出保留；未知 schema、authoring 版本或 requiredCapabilities 阻止。旧稿缺快照时保留旧契约并报告，需选择原始源重新定义；不会由拉伸实例反推原图。
- XMP 沿用 nodes/assets，writeMetadata每次写后立即回读。命中GameUI metadata属性但JSON解析失败时抛`GAMEUI_METADATA_INVALID`并保留非枚举cause，错误消息不包含XMP正文；无该属性的未标记稿仍返回null。目录先存后写 XMP，XMP 失败最多留下未使用目录条目；PSD 的未提交修改由 modal history 回滚。文件写入断电原子性不在当前宿主 API 保证范围，目录解析异常会显示并保留原文件，不静默覆盖。
- 真实 PS UI、保存重开、宿主透明 RGB 保真、蓝湖上传及 Unity 最终表现由负责人统一验证；专项 Node 通过不代表这些宿主验收已完成。

API 依据：[Adobe Imaging API](https://developer.adobe.com/photoshop/uxp/2022/ps-reference/media/imaging)、[Layer duplicate](https://developer.adobe.com/photoshop/uxp/2022/ps-reference/classes/layer)。

新建资源会拒绝与目录中已有资源相同的显示名称，提示使用选择器引用；独立资源应使用不同名称。发布同一资源的新版本仍可沿用名字。已存在或导入的同名同版本条目会显示不同的“条目 N”，选项值始终为完整 assetRef，不按名称或像素合并。条目序号只用于当前列表识别，诊断引用仍显示在资源信息中。

## 负责人可选宿主诊断入口

`Panel/host-smoke.psjs` 仅供负责人通过 Photoshop 的 Scripts/Browse 手动运行，从源码目录 require 上一级模块（不包含在插件 staging 中）。选择审计输出文件夹，脚本只读取当前已打开的 `LanhuGameUIProductionFirst20261117.psd` / `LanhuGameUIProductionSecond20261117.psd`，严格检查固定源 layer ID 3/7/11、名字与坐标。透明/软边源显式四边留白2px，均输出64×48源PNG。随后对每份合成稿创建临时副本，仅将副本透明源应用128×80、核对实际124×76内容与画布原点312,32，finally关闭副本且不保存。报告为`gameui-panel-target-host-smoke-result.json`；错误写报告，不采集其他稿件。不修改原稿、不写XMP、不保存PSD、不上传。该诊断仅验证真实宿主采集/应用，不代替面板加载、点击及持久化验收。

`Panel/resource-readback.psjs` 用于已经由美术通过面板标记、正常保存并重开的上述两份固定合成稿。先用独立 PSD 检查器从磁盘提取 `saved-panel-first-metadata.json` / `saved-panel-second-metadata.json`，放在所选审计输出目录。脚本只读比较重开后的完整 XMP、资源/实例身份与 target，采集已标记 layer 3 的真实目标 PNG，输出 `gameui-panel-resource-readback-result.json`。它不补写缺失标记，也不把不同 assetRef 按相同像素合并；目标 PNG 应再由独立参考比较。
